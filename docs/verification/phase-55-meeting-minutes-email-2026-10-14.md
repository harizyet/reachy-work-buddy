# Phase 55 verification: supervised meeting-minutes email (2026-10-14)

Branch `feature/meeting-minutes-email`. **Nothing deployed, no production data or credential touched, no real email sent, no APK released.** Labels: *unit* = in-process mocks and in-memory stores; *Mailpit* = a real SMTP server (`axllent/mailpit` v1.31.2 with STARTTLS required, a test CA and one SMTP account) in a throwaway container; *fake SMTP* = a tiny in-test server that produces outcomes Mailpit cannot (accept-but-never-answer, refused recipient, deferral); *PG* = a disposable `pgvector/pgvector:pg16` container (removed); *browser* = real Chromium against a real hub and a real core with the real sender and dispatch loop and a capturing SMTP fixture; *emulator* = Android API 34 AVD against the same fixture. **Not done:** a real Gmail account or any real mailbox, a physical phone, the owner's UAT.

## Stage G scenarios

| Scenario | Evidence |
|---|---|
| Sending to the owner's own test inbox, successful delivery with matching subject, body and attachment | Mailpit: subject, text body, To/Cc, Message-ID, and the PDF's SHA-256 equal what was approved; **browser**: the delivered message (captured on the wire) matches the on-screen review and the attachment fingerprint the owner saw; **emulator**: delivered to the fixture, the app shows "Sent" and the server's reply |
| Gmail authentication failure | Mailpit: wrong password at verify and at dispatch: "authentication failed", the password is not echoed anywhere (response, event, row), nothing delivered, **not retried** (one attempt) |
| Missing or expired sender credentials; sending disabled | unit and Mailpit: no credential, disabled sender, no sender configured: `SendRefused`, draft FAILED, nothing sent; a meeting package never falls back to the `SMTP_*` environment |
| Incorrect or missing recipient addresses | unit: 11 malformed/unsafe forms (CRLF header injection, display names, quoting, bad domains) refused; at least one To required before approval; dedupe and 20-recipient cap; fake SMTP: a refused recipient is final (FAILED) |
| Recipient changes after approval; minutes edited after approval | unit (6 parametrised changes: To, Cc, Bcc, subject, body, attachment): the message returns to READY_FOR_REVIEW, the approval is cleared, the earlier hash cannot approve, nothing is sent; **browser**: edit after approve needs a new approval |
| Speaker names corrected before preparing | unit: outputs older than the speaker names block preparation (409) until rewritten; the rewritten text carries the new name; names changed after preparing block queueing until refreshed |
| Attachment generation failure | unit: unencodable text reports why, the message has no attachment and carries the minutes in the body instead (found a bug: the body used to claim an attachment that did not exist; fixed); a missing or altered stored attachment fails the message before any send (unit, Mailpit, PG) |
| Queued email cancellation | unit, **browser**: cancel returns it to APPROVED, nothing is ever sent (waited past the window) |
| SMTP timeout and ambiguous acceptance | fake SMTP: the server receives the whole message then never answers: UNKNOWN_DELIVERY, **never resent**, the server saw exactly one copy; owner settles: "arrived" or "send again" (fresh approval, new Message-ID) |
| Worker restart during dispatch | unit, Mailpit, PG: a row left SENDING by a dead process becomes UNKNOWN_DELIVERY at start-up and is not resent; a merely slow send is left alone by the periodic check |
| Duplicate send requests | unit and PG: a second approve or queue is refused (409); 4 to 8 concurrent workers: exactly one claim and one delivery (Mailpit: exactly one message); `SKIP LOCKED` gives distinct drafts to distinct workers |
| Unauthorized API and voice-origin attempts | hub: every route 401 without a session and with the bearer alone, 403 without CSRF; core: 401/403 without the service token; service layer refuses `VOICE` for approve, queue and settle; chat/voice "send/approve draft" cannot touch a package; a voice request can only **prepare** a draft with no recipients |
| Confidential or restricted content | unit: a sensitive meeting needs an explicit acknowledgement recorded in the approved source; transcript text, audio and pending/dismissed/out-of-date findings never appear in the body, PDF or delivered message (also checked on the wire) |

## Other results

- **Real SMTP security:** STARTTLS is negotiated by us with certificate verification (a self-signed server is refused by default); credentials are never sent unencrypted (an authenticated `security: none` sender is refused at save and at send); Bcc is an envelope recipient only and appears in no transmitted header (checked on the wire). **A real defect found by Mailpit:** the SMTP library upgrades to TLS automatically with its own defaults before our explicit call, so our TLS settings were never applied; automatic upgrade is now disabled.
- **PostgreSQL:** migration 036 and its rollback (deletes meeting drafts, history, sender settings, groups and the stored credential; plain drafts survive); the sender credential is only ciphertext in `secrets` and absent from `mail_sender` and a dump; rotation re-encrypts in place and switches sending off; disconnect deletes it.
- **Tests:** core `test_meeting_email.py` 67, `test_meeting_email_mailpit.py` 16, `test_meeting_email_postgres.py` 12; hub `test_meeting_email_hub.py` 38; web vitest `meeting-email.test.tsx` 15; Playwright `meeting-email.spec.ts` 3 (real delivery, cancel, phone width); Android JVM `ShareMinutesTest` 13.
- **Full runs on this branch:** core **2878 passed, 2 failed**, 9 skipped (Postgres and Mailpit tests enabled); the 2 failures (`test_knowledge_index::test_reconcile_repairs_a_missing_stale_orphaned_and_expired_index`, `test_knowledge_retrieval::test_historical_mode_reaches_the_prefilter_and_revalidation`) fail identically on pristine `main` and are the baseline failures listed in HANDOVER. Hub and shared **589 passed**. Android JVM **168 passed** (working tree; see the first limit below). Web vitest **371 passed** (31 files), `tsc` and build clean. Full Playwright (desktop and mobile): **134 passed, 9 failed, 9 skipped**; the 9 are exactly the nine from the [Phase 54 record](phase-54-speaker-identification-2026-10-14.md) (notepad and planner specs, identical on pristine `main`); all of `meeting-email.spec.ts`, `speakers.spec.ts` and `analysis.spec.ts` pass. ruff clean.
- **Existing tests changed:** every older migration-chain test now undoes 036 first and expects head 036; `test_mark_sent` queues and claims before marking sent (the unguarded shortcut is refused by design); the SMTP-credential test patches the sender's client class instead of `aiosmtplib.send` (same assertions: reference over environment password, STARTTLS before the credential, fail closed).
- **Behaviour change to know about:** the older conversational draft path now fails a draft addressed to something that is not a plain email address instead of sending it with a malformed header.
- **Emulator** (real UI, density set for the rail layout, same as Phase 54): the Share minutes chip appears only because the hub reports the feature on; prepare, edit and save recipients, the in-app PDF preview rendered the real attachment, typed SEND, queued with its send time and a Cancel button, delivered, "Sent" with the server reply. The emulator has no audio and its bottom bar is hidden by a known IME quirk; neither matters here.

## Limits and open items

- **Android unit tests are not in git.** `.gitignore` line 23 (`test/`, meant for a private recordings folder) also matches `clients/android/app/src/test`, so *none* of the Android JVM tests is tracked (`git ls-files clients/android/app/src/test` is empty): the 146 older ones, Phase 54's 9 and this phase's 13 exist only in the working tree on the machine where they were run. The Android counts in these records are from that working tree. Anchoring the rule (`/test/`) would track them all at once; that is a separate decision for the owner and is not done here.
- **No real Gmail test.** Everything real was against Mailpit and fixtures. Gmail-specific behaviour (app-password policy, rate limits, rewriting of From to a verified alias, delivery to spam) is the owner's UAT.
- Delivery to the mailbox cannot be confirmed by SMTP: `SENT` means the server accepted it. There are no bounce notifications.
- The PDF is plain monospaced text (stdlib writer); characters outside Windows-1252 cannot be shown (the message can still go without it). A richer layout needs a PDF library.
- Calendar suggestions use the nearest event within 20 minutes of the meeting start and only for feed events; Google-sourced events carry no attendee list here.
- Decisions are labelled "not individually confirmed" because Phase 31 has no per-decision confirmation.
- Android: sender setup and group management are web-only (by design); no automated UI test beyond JVM logic and the emulator walk-through.
- Existing summaries stale against speaker names must be rewritten before a package can be prepared (a Phase 54 consequence).
- Nine pre-existing Playwright failures (notepad and planner specs) are unchanged and out of scope; see the Phase 54 record.
