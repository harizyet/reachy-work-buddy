## Characterisation before implementation

Hub behaviour was pinned with `test_planner_*` through the owner-session chain before any React code: 401 without a session and 403 without the CSRF header on mutations; task create/complete/reopen/rename/delete, the `status` filter, 404 for unknown ids, 422 for empty or oversized text, refusal of `sensitivity` on edits; reminders (offset preserved as an instant, complete and delete only, no reopen or edit); notes (search `q`, size limits, refusal of reclassification, 404 on a second delete); receipts (read-only, newest first). The legacy UI cases already in `clients/operator-ui/tests/{planner,notes,activity}.test.cjs` were read and each reproduced in the React tests.

Two further bugs were found by the tests and fixed before commit: an unsaved note edit was sent after sign-out began (React state lagged the unmount), and New note was unreachable on a phone-width screen with no note open (the jsdom tests could not see it; the browser suite did).

## Stability

Three consecutive full Playwright runs after the last change passed 60 of 60 (earlier runs of the same day failed on test mistakes: `.check()` on a control that the reload removes, a stale cookie in the shared browser context, a role query on a hidden element, and a sign-in helper that did not wait for the session check; none was an application fault except the phone-width New note button noted above).
