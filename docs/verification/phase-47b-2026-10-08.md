## Method

Each feature group started with hub characterisation tests through the owner-session chain (status codes, validation, the CSRF header, owner-bound limits, masked secrets, 404s), then the React page, then component tests reproducing the legacy fixture cases, then Playwright against the real hub. Where the legacy UI can do the same thing, a round trip checks both clients against one hub (tasks, reminders, notes).

Counts by area (Vitest): shell and Overview 15, client and generation 8, parsers 3, planner 11, notes 9, activity 4, alarms 8, chat 15, meetings 22, settings 16, voice and animations 10, accounts and coding credentials 12, owner recognition 7, coding agents 11, session isolation 17 (one run twice). Playwright: 8 in `web.spec.ts` and 20 in `planner.spec.ts`, each run at two widths and, for most, two mounts.

## Bugs the tests found (all fixed before commit)

1. An unsaved note edit was sent after sign-out began (React state lagged the unmount that triggers the last flush); the editor now uses the session generation.
2. New note was unreachable on a phone-width screen with no note open (jsdom has no CSS; the browser suite found it).
3. A second save of an unchanged masked key left the typed key in the password field (the form did not remount).
4. A wrong owner-recognition re-confirmation password signed the owner out (the legacy page does the same; the hub uses 401 for both a lost session and a refused confirmation).
5. Voice samples were rejected by the hub: a browser recorder reports `audio/webm;codecs=opus`, the hub matches `audio/webm` exactly (the legacy page has the same fault in Chromium). The React page sends the bare type.

Playwright failures that were test mistakes, not application faults: `.check()` on a control the reload removes, an in-flight response resurrecting a cookie the test had cleared (the hub re-sets the session cookie on every response), a role query on a hidden element, and a sign-in helper that did not wait for the session check.

## Not verified

No deployment, no Caddy (a prefix-stripping proxy stands in), no production data. No real robot was commanded (animation and microphone settings were exercised on the simulated robot; the real microphone path is the browser's fake device). Google, Telegram, the coding-agent service, the model manager (deep review) and TuneIn search are not present on a test hub, so those paths are fixture-tested only and need the owner's user test. Time-zone and locale behaviour was exercised in the machine's own locale. No screen-reader pass. The legacy-to-React round trips run in one browser context against one simulated hub.
