## What the tests cover

- Data: a seeded generator reproduces the same graph; every record is labelled synthetic and unmistakably placeholder; clusters are separated; links are explicit only, join only the kinds that really relate, each with a stated basis; paging is bounded and cursor-based with a server-side cap; edges never reference a node outside the request; counts match what the filters return.
- Page (component level, scene stubbed): synthetic banner; no request to the hub (a failing `fetch` stub); list fallback; search and kind filters; details are literal text; following a link to a hidden record clears the filters; a selection the filters hide is dropped; the unavailable-features note is present and nothing else pretends to be relationships or activity; a failing source shows an error with retry; the scene receives the visible set, particle ceiling, links toggle, reset and selection; phone width and reduced motion start light.
- Browser (real WebGL): the canvas is created and non-blank; the 3D chunk is not requested until the page opens; no hub request for Brain data; keyboard-only search, filter, select and reset; a click on a dot in the 3D view selects it; WebGL unavailable gives the list and never fetches the 3D chunk; reduced motion renders only on change; a hidden tab stops drawing and a visible one resumes; leaving the page loses every WebGL context; no horizontal overflow on a phone-width screen.

## Not verified

Integrated graphics and phones (only software rendering was available); texture and GPU memory use beyond JS heap and context loss; long sessions; a screen-reader pass (the list is the intended path and is plain HTML); the visual result judged by the owner (the browser tests check that something bright is drawn and that picking works, not that it looks right).
