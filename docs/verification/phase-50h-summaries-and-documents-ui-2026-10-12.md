# Phase 50H, 50D, 50G and a minimal 50J (2026-10-12)

Local development while the MS-01 deployment gate waits for the owner's approval ([sequence](../phase-50.md#0-revised-execution-sequence-owner-decision-2026-10-12)). **Nothing deployed; nothing activated; no production backup, migration or recreation.** Migration `031_documents` (still undeployed) now also creates `document_outputs`; `rollback-031.sql` drops both.

## What was built

* **50H summaries** (`document_library/summary.py`, service, routes): ordinary, executive and technical, local model only, bounded page groups (map, merge in batches, final style), derived-interpretation outputs with the original's hash, tier, model and prompt version, inherited class, stale-on-reprocess, removal with the document, background run with restart cleanup, sparse-text refusal. Reference: [services](../reference/services.md#document-library-phase-50b-50c).
* **50G provenance:** citations (and summary sections) carry the document id, source hash, extraction tier, `evidence_type` and the page-level locator of the page that was supplied or summarised; nothing is a page the model wrote.
* **50D Advanced:** `advanced` is an ordinary worker tier (same worker, same models, no new infrastructure), `next_tier` ladder, never automatic. Spike: Advanced parsed a 2-page scan correctly in about four minutes on CPU, so it is a deliberate last resort.
* **Worker search rewritten (found by the first real-model run):** MinerU's library-wide search returns one snippet per document, so the earlier snippet-to-page matching returned page `None` for most hits and document Q&A answered "I couldn't find that" to questions the document answered. The worker now ranks the document's own parsed pages (`ranking.py`), so every hit has the page that was scored, nothing of another document can appear, and the library-wide search is no longer called.
* **50J minimal Documents UI:** hub proxy `reachy_hub/document_library.py` (owner session plus CSRF, sets the sensitive ceiling itself, ignores a browser-supplied ceiling, fixed errors) and the web Documents page (upload with class, project and priority; list; detail; rename and re-class; read again; improve reading; delete with confirmation; Ask; Search; three summary styles with provenance and stale marking).
* Document-ceiling and the 204-aware web client.

## Verification

* **Worker** (21 tests): ranking tests (scoped, the answering page first, nothing found and no guessed page, incomplete for long documents) among them.
* **Core** (`test_document_library.py`, 52 tests): summaries (one call and provenance; bounded page groups with each group's pages and the final step reading notes not raw pages; page bound reported; sparse text refused with a tier pointer; class and ceiling; stale after reprocess; deleting removes outputs and cancels a running one; failures and restart cleanup; no local model), escalation to Advanced, plus the 50E tests. **Hub** (`test_document_library_proxy.py`, 5 tests): owner session only (anonymous and bearer refused), CSRF, upload to delete, hub-set ceiling, flag-off 404s, core-down 502 without details. **Web** (`documents.test.tsx`, 10 tests; whole suite 262 passed): literal rendering, off state, upload multipart with CSRF, ask, search, summaries, failed summary explanation, improve/rename, delete confirmation. Real PostgreSQL (disposable container, removed): outputs store, one current output per key, supersede, restart cleanup, delete: the five opt-in suites 64 passed, 1 skipped.
* **Real engine, real model (labelled: not a mock):** core in process, the real worker image running real MinerU, and the real local model (production vLLM, `reachy-local`, a handful of short requests through its published loopback port; production core and its Phase 48 telemetry were not involved) on a 7-page vendor-requirements PDF: Q&A answered correctly with the right pages (audit log retention: 90 days online and one year archive; first compliance deadline: end of the month following signature; incident contact: the email and telephone), and abstained on an unrelated question; executive, technical and ordinary summaries were accurate and bounded (about 14 to 23 s each, sections by page group, 7 of 7 pages covered); the work-private ceiling got 403 on a sensitive document's summaries.
